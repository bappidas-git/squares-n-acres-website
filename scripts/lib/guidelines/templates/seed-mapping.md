`db.json` in this folder is a byte copy of the repository's seed: the same data
the mock serves and the same data every screenshot, test and example in this
package was made from. Importing it gives you a database the frontend renders
completely, which is the fastest way to find a field you have not implemented
yet.

Write the import as a Laravel seeder that reads the file, not as a hand-written
SQL dump: the JSON is the source of truth and it will be regenerated.

## Preserving ids

**Insert with the ids the seed carries.** Every `propertyId`, `localityId`,
`amenityIds[]` and `similarPropertyIds[]` in the file points at them, and so do
the examples in `03_ENDPOINTS.md`, the Postman collection and the smoke test
(`example: 1`, `example: 'whitefield'`).

```php
DB::table('properties')->insert($rows);      // ids included
DB::statement('ALTER TABLE properties AUTO_INCREMENT = ' . (max(ids) + 1));
```

Reset each table's `AUTO_INCREMENT` above the highest imported id afterwards, or
the first record an editor creates collides.

**The ids inside nested arrays are different.** `images[].id`,
`floorPlans[].id`, `notes[].id` and the rest are local to their parent document
and repeat across records — property 1 and property 2 both have an image with
`id: 1`. Child tables get their own `AUTO_INCREMENT` primary key; keep the
original only if you want it, in a column of its own. Nothing in the contract
references them across records.

## Extracting the pivots and child rows

For each property, insert the parent row without its nested arrays, then:

```php
foreach ($property['images'] as $i => $image) {
    DB::table('property_images')->insert([
        'property_id' => $property['id'],
        'url' => $image['url'], 'alt' => $image['alt'],
        'caption' => $image['caption'] ?? null,
        'order' => $image['order'] ?? $i, 'is_cover' => $image['isCover'] ?? false,
    ]);
}

DB::table('property_amenity')->insert(collect($property['amenityIds'])
    ->map(fn ($id) => ['property_id' => $property['id'], 'amenity_id' => $id])->all());

DB::table('property_similar')->insert(collect($property['similarPropertyIds'])
    ->map(fn ($id, $i) => ['property_id' => $property['id'],
                           'similar_property_id' => $id, 'position' => $i])->all());
```

`property_similar` points at properties that may not be inserted yet, so run the
three pivots in a second pass after every property row exists.

## The singleton settings

`siteSettings` and `seoSettings` are objects, not arrays. Each becomes **one
row** with `id = 1` and one JSON column per top-level group:

```php
DB::table('site_settings')->insert([
    'id' => 1,
    'general' => json_encode($seed['siteSettings']['general']),
    'hero' => json_encode($seed['siteSettings']['hero']),
    // … one per group
    'updated_at' => now(),
]);
```

`PUT /admin/settings` deep-merges into that row (see `05_BUSINESS_RULES.md`), so
the groups must survive as objects rather than being flattened into columns.

## What not to import

- **`apiTokens`** — the mock's token store. Laravel Sanctum owns
  `personal_access_tokens` and creates it with its own migration. The table in
  `schema.sql` is there so nothing in the model is undocumented; do not create
  it.
- **`media`** — optional. The records point at Cloudinary and `picsum.photos`
  URLs; importing them gives the media library something to show, and skipping
  them costs nothing. No other record depends on a media row: a property's
  images carry their own URLs.
- **`propertyViews`** — analytics fixtures behind the dashboard's 30-day trend.
  Import them if you want a populated chart on day one; they carry no meaning.

## Passwords

`adminUsers[].password` is **plaintext in the seed**. Hash every one on import:

```php
DB::table('admin_users')->insert([
    // …
    'password' => Hash::make($user['password']),
]);
```

and rotate all three before the API is reachable from anything but `localhost`.
The three seed passwords are published in this package — see
`02_AUTH_AND_RBAC.md` and step 2 of the go-live checklist in `07_DEPLOYMENT.md`.

## Verifying the import

```bash
npm run mock                                  # the reference, on :4000
npm run smoke -- --baseUrl=<your API> --compare=http://localhost:4000/api
```

An empty difference table means the two servers answer the same shapes about the
same data. Then spot-check three records by hand: property 1, locality
`whitefield`, and the lead with the longest activity trail.
