# The API smoke test

The walk the website repository runs as `npm run smoke`, packed so that it needs
nothing but **Node 20 or later** — no `npm install`, no repository. It signs in
as the three roles, calls every endpoint of the registry with the smallest
request that should succeed, checks the status and the envelope, runs the
behaviour checks a status code cannot show, and deletes what it created.

Generated by `npm run generate:smoke-bundle` (and by
`npm run generate:backend-guidelines`) — do not edit these files.

## The three commands

```bash
# 1. The local mock — the reference the API is built against
node smoke-api.js

# 2. Staging — the full walk: it creates, edits and deletes records
node smoke-api.js --baseUrl=https://staging.example/api --allow-writes

# 3. Production — the read checks, signed in as a real account of each role,
#    then the comparison with the local mock (which keeps the seed's admin)
node smoke-api.js --baseUrl=<production API> --email=<admin> --password=<…> \
  --managerEmail=<manager> --managerPassword=<…> --salesEmail=<sales> --salesPassword=<…>
node smoke-api.js --baseUrl=<production API> --email=<admin> --password=<…> \
  --compare=http://localhost:4000/api --compareEmail=admin@squaresnacres.com --comparePassword=Admin@123
```

The production API is `https://www.squaresnacres.com/api` when the site and the
API share one host (Layout A of `07_DEPLOYMENT.md`) and
`https://api.squaresnacres.com/api` when they do not (Layout B). In the website
repository the same run is `npm run smoke -- <the same options>`.

## Write safety

The walk **writes only to this machine** (`localhost`, `127.*`, `[::1]`)
unless `--allow-writes` is passed — which is for staging. Against any other host
it runs the read-only subset: every `GET` of the registry except
`redirects.resolve` (it counts a hit), signing in and out, and the checks that
only read; under the table it names what it left out and why. `--read-only`
asks for that subset on this machine too.

**Production only ever gets the read checks and `--compare`.** The full walk and
the Postman collection run against staging.

## Options

| Option | Default | |
| --- | --- | --- |
| `--baseUrl` | `http://localhost:4000/api` | the API, `/api` included |
| `--email`, `--password` | the seed's admin | the admin the run signs in as |
| `--managerEmail`, `--managerPassword`, `--salesEmail`, `--salesPassword` | the seed's | the other two roles |
| `--allow-writes` | off | run the full walk against a host that is not this machine (staging) |
| `--read-only` | off | run the read-only subset even on this machine |
| `--compare=<url>` | — | send every read to both servers and print only the differences of shape |
| `--compareEmail`, `--comparePassword` | `--email`, `--password` | the compared server's admin, once passwords were rotated |
| `--verbose` | off | print every request, and every entry a read-only run left out |

It exits 1 when a check fails or a comparison differs, so it can gate a deploy.
