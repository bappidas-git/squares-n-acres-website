## 2. Objective
When this prompt is finished the new property form architecture exists under `src/pages/admin/properties/property-form/` and is mounted at `/admin/properties/add` and `/admin/properties/edit/:id`: a reducer-based `usePropertyForm` with the typed initial state of §6.1, section-level validators, dirty tracking, draft autosave (10 s when dirty) with a restore banner, unsaved-changes guard, `toPayload()` returning the exact camelCase record, `fromRecord()` loading an admin record, the 16-tab shell with per-tab error badges and a **status rail** (active/featured/verified toggles, availability, priority, completeness meter, slug + "View on site", last saved, Save / Save & continue / Save & view / Save as inactive, Duplicate, Delete), server 422 → tab jump. Tabs 1–16 render placeholders ("Tab content arrives in prompt 19/20/21") except the shell-level fields; saving **works end-to-end** for the fields the shell owns (title, slug, listingType, segment, propertyTypeId, constructionStatus, availability, status toggles) because `toPayload()` fills every other field from state defaults. The legacy `PropertyForm.jsx`, `property-tabs/*` and adapters for the form are deleted at the end of prompt 21 (not here).

`ownership null`, `reraNumber null`, `reraRegistered false`, `description ''`, `shortDescription ''`, `highlights []`, `amenityIds []`, `badgeIds []`, `specifications []`, `constructionSpecs []`, `unitConfigurations []`, `floorPlans []`, `images []`, `videoUrl null`, `virtualTourUrl null`, `brochureUrl null`, `brochureLeadGated true`, `documents []`, `location { address '', localityId null, cityId null, pincode '', landmark '', latitude null, longitude null, mapEmbedUrl null, showExactLocation false }`, `nearbyPlaces []`, `pricing { price null, priceOnRequest false, priceRangeMin null, priceRangeMax null, pricePerSqft null, priceNegotiable false, rentPerMonth null, securityDeposit null, maintenanceChargesMonthly null, bookingAmount null, otherCharges [], currency 'INR' }`, `area { superBuiltUpArea null, builtUpArea null, carpetArea null, plotArea null, areaUnit 'sqft', plotLength null, plotWidth null, plotDimensionUnit 'ft' }`, `configuration { bedrooms null, bathrooms null, Nested list item factories: `makeImage()`, `makeUnitConfiguration()`, `makeFloorPlan()`, `makeDocument()`, `makeNearbyPlace()`, `makeSpecification(group)`, `makeConstructionSpec(group)`, `makeTimelineItem()`, `makeFaq()`, `makeOtherCharge()` — each with a client-side temporary id `tmp-<n>` (stripped by `toPayload` → the server assigns ids; existing numeric ids preserved).
2. **`reducer.js` + `usePropertyForm({ propertyId })`.** Actions: `LOAD(record)`, `SET(path, value)` (dotted paths, arrays by index), `LIST_ADD(path, item, index?)`, `LIST_REMOVE(path, id)`, `LIST_MOVE(path, from, to)`, `LIST_UPDATE(path, id, patch)`, `SET_MANY(patch)`, `SET_ERRORS(errorsByTab)`, `CLEAR_ERROR(path)`, `MARK_SAVED(record)`, `RESTORE_DRAFT(draft)`, `RESET`. State: `{ values, initial (last saved), errors { [path]: msg }, touched, dirty (deep compare vs initial — use a cheap JSON.stringify diff memoised on values), saving, lastSavedAt, isNew, restoredDraft }`. The hook returns `{ state, values, errors, dirty, setField, addItem, removeItem, moveItem, updateItem, validateTab(key), validateAll(), save(mode: 'save'|'continue'|'view'|'inactive'), duplicate(), remove(), errorsByTab, completeness }`. **Autosave:** every 10 s while `dirty`, write `{ values, savedAt }` to `sna_property_draft:<id|new>`; on load, if a draft exists newer than the record's `updatedAt` (or for `new`), show `DraftBanner` "Restore unsaved draft from 5 minutes ago?" (Restore / Discard); draft cleared after a successful save. **Unsaved guard:** `useUnsavedChanges(dirty)`.
3. **`fromRecord(record)`** → values (fills missing keys with defaults; converts `null` strings; sorts lists by `order`; sets `seo` defaults) and **`toPayload(values)`** → the exact write shape: strips read-only/embedded fields, tmp ids, empty list rows (a row is empty when all its user fields are blank), normalises numbers (`''` → `null`), trims strings, computes `pricing.pricePerSqft` when missing (`price / superBuiltUpArea` rounded) — editable so only when null, ensures one `isCover` (first image when none), sorts `order` fields 1..n, mirrors `seo.slug = slug`, drops `seo.score/analysis` (kept as computed; the SEO panel writes them in 36 — pass through unchanged when present), keeps `similarPropertyIds` ≤ 6. Tests: round-trip `fromRecord(toPayload(values))` stable; empty rows removed; cover ensured.
4. **Validators (`validators/property.js`)** per PROP-03: `title` ≥ 10; `slug` required + pattern; `listingType`, `segment`, `propertyTypeId`, `constructionStatus`, `availability`, `location.localityId` required; `possessionDate` required for pre-launch/under-construction and must be a valid date; sale: `pricing.price` or `priceOnRequest` or (`priceRangeMin` & `priceRangeMax`, min < max); rent/lease: `rentPerMonth` required; numeric fields ≥ 0; `latitude` −90..90, `longitude` −180..180; URLs valid (`https?://`); `images[].alt` required when `url` set; `unitConfigurations[]`: `name` + (an area or a price); `faqs[]`: both fields; `documents[]`: title + url; `similarPropertyIds` ≤ 6 and not self. **Activation rules (`validateForActivation`)** — blockers only when `isActive` is true: ≥ 1 image with alt, `description` ≥ 300 characters (plain text), `shortDescription` non-empty; warnings (non-blocking, shown in the rail): description < 300 words, < 8 amenities, no FAQs, no floor plan/unit configuration, no RERA number for projects. Errors are keyed by dotted path and grouped by tab via `tabs.js` `fields` prefixes (`errorsByTab`).
5. **`completeness.js`** — `computeCompleteness(values)` → `{ percent, items: [{ key, label, done, weight }] }` with weights: basics 10, description ≥ 300 chars 10, cover + ≥ 5 images with alt 15, pricing 10, area & configuration 8, amenities ≥ 8 → 8, highlights ≥ 3 → 4, location with coords 8, unit configurations/floor plans 6, documents/brochure 4, nearby ≥ 3 → 4, FAQs ≥ 3 → 5, developer/project 3, SEO title+description+focus keyword 5 = 100.
6. **`tabs.js`** — the 16 tabs in this order with keys/labels/icons/field prefixes: `basics` "Basics", `location` "Location", `pricing` "Pricing", `area` "Area & configuration", `units` "Unit configurations", `media` "Media", `amenities` "Amenities", `highlights` "Highlights & specifications", `floorPlans` "Floor plans", `documents` "Documents", `project` "Project & builder", `faqs` "FAQs", `similar` "Similar properties", `visibility` "Section visibility", `agent` "Agent", `seo` "SEO". Each maps to a component (placeholders now; real components in 19–21; SEO panel in 36). `AdminTabs` shows `errorCount` per tab.
7. **Shell + rail.** `PropertyFormPage` loads the record (`propertyService.adminGet(id)`; 404 → admin `EmptyState` "Property not found" + back link), initialises the hook, renders `PageHeader` (title "Add property" / "Edit: <title>", breadcrumb Properties), two-column layout (form 1fr + rail 320 px sticky ≥ 1200 px; stacked below with the rail's primary actions duplicated in a sticky bottom bar on mobile), `AdminTabs` + active tab content, `DraftBanner`. `StatusRail`: toggles `isActive` (label "Published on site" — when turning on, run `validateForActivation`; blockers → toast + jump to the first tab with a blocker), `isFeatured`, `isVerified`; `availability` select; `priorityOrder` number; completeness meter (`LinearProgress` + percent + expandable checklist); slug row with "View on site" (`SITE.url + /properties/<slug>`, disabled when inactive or new); "Last saved 2 min ago" (`formatRelative`); buttons: **Save** (`save('save')` → toast, stay), **Save & continue** (same, alias for clarity — decision: keep one primary "Save" plus a split menu with "Save & view", "Save as inactive"; record), **Duplicate** (edit mode: `propertyService.duplicate(id)` → navigate to the copy), **Delete** (confirm → `remove` → navigate to the list). Sales role: whole form read-only (`disabled` inputs, no actions; banner "Read-only access").
8. **Save flow.** `save(mode)`: `validateAll()` (+ activation rules when `isActive`) → on errors: `SET_ERRORS`, jump to the first tab with errors, toast "Please fix N fields"; else `create`/`update` (PUT with `toPayload`) → `MARK_SAVED(record)` (server record → `fromRecord`), clear draft, toast; mode `view` → open the public URL (new tab); mode `inactive` → sets `isActive false` before saving; server 422 → `setServerErrors` (dotted keys → tabs) + jump; 409 slug → slug error with suggestion. Navigation after create: replace URL with `/admin/properties/edit/<id>`.

## 6. UI/UX requirements
Rail card on white with tokens; toggles with descriptions; completeness meter coloured by band (error < 40, warning < 75, success ≥ 75); tab bar scrollable with error badges (red count); mobile: tabs as a horizontal scroll, rail collapsed into a "Status" accordion at the top + sticky bottom bar (Save primary); every field labelled; unsaved guard dialog on navigation; autosave indicator "Draft saved 10:42" in the rail.

## 7. Edge cases that must work
- Opening `/admin/properties/add`, typing a title, waiting 10 s, reloading → draft banner → Restore fills the form.
- Turning "Published" on without images → blocked with a clear message and tab jump; saving as inactive with the same data → allowed.
- Server 422 on `location.localityId` → Location tab badge + inline error.
- Duplicate slug on create → 409 → suggestion applied on click.
- Sales user opening the edit URL → read-only; no autosave.
- `toPayload` never sends `tmp-` ids, embedded objects or counters.
