### 1.C — The media library (the human's second complaint)

The library's model is right — folders are strings on records, files upload straight to Cloudinary with an unsigned preset (D12) — but three things make it feel broken:

1. **"I can't create a folder."** The only folder inputs are free-text boxes *inside* the upload zone (hidden entirely until Cloudinary is configured and Upload is clicked) and inside the Add-by-URL dialog and edit drawer — all styled as plain text fields with a browser `datalist`, which reads as "pick an existing folder". The visible, always-present Folder control on the page is the **filter select**, which genuinely only offers existing folders. There is no "New folder" affordance anywhere, and nothing explains that a folder is created by filing a file into it.
2. **No management:** no bulk selection in the library (the mock's guarded bulk delete exists at `mock-server/routes/media.js` and nothing calls it), no move-to-folder, no folder rename (a typo'd folder is permanent), no "not used anywhere" filter, and every listing photo lands in one flat `properties` folder — 284 of the 389 seed files (`ImageGalleryEditor.jsx` ~26 hardcodes it) — which the 18-per-page picker then paginates hopelessly.
3. **"I'm not sure how to upload to Cloudinary."** Settings → Integrations offers two bare boxes (cloud name, unsigned upload preset) with one-line hints. There is no walkthrough of where these come from, no "Test uploads" button, and a wrong preset only fails later, mid-upload, with a raw Cloudinary error.
